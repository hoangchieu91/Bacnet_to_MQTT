📟 Modbus RTU Sniffer & Diagnostics

Công cụ chẩn đoán bus Modbus RTU từ tầng vật lý đến ứng dụng. Hỗ trợ 3 mode hoạt động với tổng cộng 23 loại chẩn đoán.

⚡ Tầng vật lý: RS-485

Differential Pair

RS-485 dùng 2 dây A(+) và B(-) truyền vi sai. Nhiễu common-mode bị triệt tiêu nhờ receiver đo hiệu VA − VB.

Không nhiễu: Có nhiễu (+2V): A = 3.5V A = 5.5V B = 1.5V B = 3.5V ΔV = 2.0V ΔV = 2.0V ← giống!

Half-Duplex & Master-Slave

Một thời điểm chỉ 1 thiết bị truyền. Master bắt đầu giao tiếp, Slave chỉ trả lời khi được hỏi.

  • Bus collision xảy ra khi 2 device TX cùng lúc → CRC fail
  • Cần 120Ω termination ở 2 đầu bus chống phản xạ sóng
  • Tối đa 32 unit loads, bus max 1200m @9600 baud

📦 Modbus RTU Frame

Cấu trúc Frame (ADU)

Modbus RTU không có delimiter — frame bắt đầu/kết thúc bằng khoảng im lặng ≥ 3.5 character times.

Slave ID
1 byte
Function
1 byte
Data
0-252 bytes
CRC-16
2 bytes (LSB)

Ví dụ: [01] [03] [00 00 00 01] [84 0A] = Read Holding Registers slave 1, register 0, count 1

CRC-16 Modbus

Polynomial 0xA001, init 0xFFFF. Phát hiện 99.998% lỗi bit.

For each byte: CRC = CRC XOR byte Repeat 8x: if bit0=1: CRC=(CRC>>1) XOR 0xA001 else: CRC=(CRC>>1) Result: LSB first in frame

🔍 3 Mode chẩn đoán

MODE 1 Passive Sniffer

USB-RS485 tap song song vào bus, chỉ RX. Không ảnh hưởng bus.

Master ─── A ───┬──── S1 ─── S2 ─── S3 │ Pi (sniffer) ───┘ ← RX only, DE=LOW

✅ An toàn 24/7   ⚠️ Không biết direction   📊 8 diagnostics

MODE 2 Inline Proxy

2 USB-RS485 chèn giữa Master và Slaves. Forward byte-level.

Master ═══ ComA ═══ [Pi] ═══ ComB ═══ Slaves segment 1 segment 2 ComA RX = Master → REQUEST ComB RX = Slave → RESPONSE

✅ Biết direction 100%   ✅ Exact response time   📊 15 diagnostics

MODE 3 Dual-Pi

Pi-1 (inline ở đầu) + Pi-2 (passive ở cuối). Cross-correlation 2 điểm.

Master ─ [Pi-1 Inline] ─ S1 ─ S2 ─ [Pi-2 Passive] [120Ω] ComA ComB tap RX [120Ω] Pi-1:8766 ←── WiFi/API ──→ Pi-2:8766 (cross-correlate)

✅ Signal degradation   ✅ Noise localization   📊 23 diagnostics

🩺 Quy tắc chẩn đoán

⬡ Mode 1 — Passive (8 rules)

1
HIGH_CRC_ERRORS

CRC fail >5% → warning. Nguyên nhân: dây hỏng, thiếu termination, EMI.

2
JUNK_BYTES

Bytes không thuộc frame nào >2%. Noise trên bus, baud mismatch.

3
BUS_SILENCE

Im lặng >5s. Master offline hoặc bus bị đứt.

4
HIGH_BUS_UTILIZATION

Bandwidth >70%. Slave có thể bị timeout do quá tải.

5
CHATTY_MASTER

Poll >50 req/s tới 1 slave. Chiếm quá nhiều bandwidth.

6
EXCEPTION_RESPONSES

Exception >10%. Slave trả lỗi: Illegal Function/Address/Value.

7
SLOW_RESPONSE

Response >500ms (heuristic). Slave xử lý chậm.

8
NO_RESPONSE

Timeout >5s (heuristic). Slave offline hoặc address sai.

⬡ Mode 2 — Inline Proxy (+7 rules)

9
EXACT_RESPONSE_TIME

tsComB − tsComA → ms chính xác, không heuristic.

10
NO_RESPONSE_EXACT

Request trên ComA, timeout trên ComB → 100% confirmed.

11
DIRECTION_VIOLATION

Frame từ ComB (slave) mà không có request trước đó.

12
LATE_RESPONSE

Response đến sau khi Master đã gửi request mới.

13
BROADCAST_RESPONSE

Slave trả lời broadcast (ID=0) → vi phạm Modbus spec.

14
DUPLICATE_SLAVE_ID

1 request → 2+ responses. 2 thiết bị cùng address.

15
FRAME_CORRUPTION_DIR

CRC OK trên ComA nhưng fail trên ComB → lỗi cáp 1 chiều.

⬡ Mode 3 — Dual-Pi Cross-correlation (+8 rules)

16
SIGNAL_DEGRADATION

CRC% Pi-2 > Pi-1 → suy hao tín hiệu theo khoảng cách.

17
SEGMENT_FAULT

Frame Pi-1 forward nhưng Pi-2 không thấy → đứt dây.

18
PROPAGATION_DELAY

Đo jitter Δt giữa 2 Pi → cable/timing anomaly.

19
TERMINATION_FAULT

So sánh CRC pattern → biết thiếu 120Ω đầu nào.

20
NOISE_LOCALIZATION

So sánh junk bytes 2 Pi → xác định vùng nhiễu EMI.

21
FRAME_LOSS

Frame loss rate per-slave → driver yếu, stub dài.

22
SLAVE_INTERFERENCE

Cross-correlate TX time + CRC → slave gây nhiễu.

23
TIMING_DRIFT

Frame duration khác nhau → baud rate / clock mismatch.

🎯 Khi nào dùng mode nào?

Mode 1 — Passive

  • Monitor bus 24/7 không ảnh hưởng
  • Kiểm tra sức khỏe tổng quan
  • Tìm slave gây nhiều lỗi nhất

Mode 2 — Inline Proxy

  • Đo response time chính xác
  • Confirm slave không trả lời
  • Debug firmware (direction violation, broadcast)
  • Tìm 2 slave cùng address

Mode 3 — Dual-Pi

  • Bus CRC lỗi random, không rõ nguyên nhân
  • Nghi ngờ cáp hỏng giữa 2 điểm
  • Tìm slave gây nhiễu bus
  • Kiểm tra termination đầu nào thiếu
